## Overview

The **GraphQL API** plugin auto-generates a full GraphQL SDL schema from your content type JSON schemas. Query content with type-safe fields, filtering, pagination, and built-in asset resolution with responsive images — and expose a locked-down public delivery endpoint for your front-ends.

## Key Features

- **Auto-generated SDL** — valid for any number of content types, with collision-free type names
- **Full filtering** — every operator the SDL advertises is executed, including `in`, `notIn`, `endsWith`, and nested `AND`/`OR`
- **Correct comparisons** — numeric and date fields compare as numbers and dates, not as text
- **Pagination and ordering** — limit, offset, orderBy ascending/descending
- **Reference resolution** — linked content items resolved automatically
- **Asset resolution** — responsive images with srcSet, breakpoints, LQIP, dominant color
- **Batch queries** — several queries in a single bounded request
- **Enforced limits** — depth, complexity, and rate limits are applied, not just stored
- **Delivery API** — token-authenticated public endpoint with persisted queries and per-token CORS

## For Admins: Configuration

### Migrations

```bash
psql -U postgres -d roadbeat_studio -f plugins/pro-graphql/migrations/001_create_graphql_config.sql
psql -U postgres -d roadbeat_studio -f plugins/pro-graphql/migrations/002_delivery_api.sql
```

Tables created: `pro_graphql_configs`, `pro_graphql_delivery_tokens`, `pro_graphql_persisted_queries`

### GraphQL Configuration

```bash
PUT /api/v1/pro/graphql/config
{
  "enabled": true,
  "playgroundEnabled": true,
  "introspectionEnabled": true,
  "maxDepth": 10,
  "maxComplexity": 1000,
  "rateLimitPerMin": 100,
  "includeDraft": false,
  "defaultLocale": "en",
  "cacheTtlSeconds": 60
}
```

<Callout kind="info">
  These limits are enforced on every query, including batch requests and the public delivery endpoint. A request that exceeds `maxDepth` or `maxComplexity` is rejected rather than executed.
</Callout>

### Schema Inspection

```bash
# Full GraphQL SDL with descriptions
GET /api/v1/pro/graphql/schema

# Raw SDL string (for IDE plugins)
GET /api/v1/pro/graphql/schema/sdl

# Content types with field mappings
GET /api/v1/pro/graphql/schema/types

# Field mappings for a specific type
GET /api/v1/pro/graphql/schema/type/:contentTypeId
```

## For Developers: Querying Content

### Single Item Query

```bash
POST /api/v1/pro/graphql/query
{
  "contentType": "news",
  "single": true,
  "id": "content-uuid",
  "locale": "en"
}
```

### Collection Query with Filters

```bash
POST /api/v1/pro/graphql/query
{
  "contentType": "news",
  "where": {
    "status": { "eq": "published" },
    "data.classification.category": { "in": ["politics", "economy"] },
    "OR": [
      { "data.priority": { "gte": 5 } },
      { "data.headline.en": { "endsWith": "(live)" } }
    ]
  },
  "orderBy": "publishedAt_DESC",
  "limit": 10,
  "offset": 0
}
```

### Filter Operators

| Filter | Operators |
|--------|-----------|
| String | `eq`, `ne`, `in`, `notIn`, `contains`, `startsWith`, `endsWith`, `isNull` |
| Number | `eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `in`, `isNull` |
| Boolean | `eq`, `ne`, `isNull` |
| DateTime | `eq`, `ne`, `gt`, `gte`, `lt`, `lte`, `isNull` |
| Combinators | `AND`, `OR` (nestable) |

<Callout kind="tip">
  Numeric and date fields stored in JSON are cast before comparison, so `{ "data.price": { "gt": 100 } }` orders `9` before `100` the way you would expect, rather than comparing them as strings.
</Callout>

### Batch Queries

```bash
POST /api/v1/pro/graphql/query/batch
{
  "queries": [
    { "contentType": "news", "limit": 5, "orderBy": "publishedAt_DESC" },
    { "contentType": "event", "limit": 3, "where": { "data.schedule.start_date": { "gte": "2026-03-01" } } }
  ]
}
```

The number of queries per batch is bounded, and each one is checked against the same depth and complexity limits as a single query.

### Asset Resolution with Responsive Images

```bash
GET /api/v1/pro/graphql/resolve/asset/:assetId?w=800&h=600&fit=cover
```

Returns responsive image data including srcSet at multiple breakpoints (320–1920px), WebP format, LQIP base64 placeholder, and dominant background color.

## Content Delivery API

The endpoints above require a Studio session. The **delivery API** is the public one — the part that makes this a headless CMS rather than a playground. It is authenticated by an organization-scoped delivery token and serves only queries you have registered.

<Steps>
  <Step title="Register a persisted query">
    ```bash
    POST /api/v1/pro/graphql/delivery/queries
    { "name": "homepage-news", "query": { "contentType": "news", "limit": 10, "orderBy": "publishedAt_DESC" } }
    ```
    The response contains the query **hash** your front-end will call.
  </Step>
  <Step title="Create a delivery token">
    ```bash
    POST /api/v1/pro/graphql/delivery/tokens
    { "name": "Website", "scopes": ["read"], "allowedOrigins": ["https://example.eu"] }
    ```
    Scopes are `read` (published content, the default) and `read:draft`. The token is shown **once** — store it in your front-end's server-side config.
  </Step>
  <Step title="Execute from your front-end">
    ```bash
    POST /api/v1/graphql-delivery/query/<hash>
    Authorization: Bearer <delivery-token>
    { "variables": { "locale": "de" } }
    ```
  </Step>
</Steps>

### Delivery guarantees

| Property | Behaviour |
|----------|-----------|
| Executable queries | Only registered hashes — a public client cannot compose arbitrary queries |
| Draft visibility | Published content only, unless the token carries the `read:draft` scope |
| CORS | Restricted to the token's `allowedOrigins`, not wide open |
| Limits | The organization's depth, complexity, and rate limits apply here too |
| Rate limiting | Per token, plus a global throttle on the endpoint |

<Callout kind="alert">
  Draft visibility is decided by the **token's scope**, not by the organization's `includeDraft` setting. A delivery token without `read:draft` never sees drafts, even when the Studio-side configuration includes them.
</Callout>

<Callout kind="info">
  The Studio-side query interface is REST-shaped rather than a traditional GraphQL endpoint. This keeps the plugin self-contained without requiring Apollo Server as a dependency.
</Callout>

## API Reference

All GraphQL endpoints are in the [Studio API Reference](https://docs.studio.roadbeat.dev/api-reference/overview) under the `pro-graphql` and `pro-graphql-delivery` tags.

| Endpoint | Description |
|----------|-------------|
| `GET /api/v1/pro/graphql/schema` | Generated schema |
| `POST /api/v1/pro/graphql/query` | Execute a query |
| `POST /api/v1/pro/graphql/query/batch` | Execute several queries |
| `GET /api/v1/pro/graphql/resolve/asset/:id` | Responsive image data |
| `GET /api/v1/pro/graphql/config` | Read configuration |
| `PUT /api/v1/pro/graphql/config` | Update configuration |
| `GET /api/v1/pro/graphql/delivery/tokens` | List delivery tokens |
| `POST /api/v1/pro/graphql/delivery/tokens` | Create a delivery token (shown once) |
| `DELETE /api/v1/pro/graphql/delivery/tokens/:id` | Revoke a token |
| `GET /api/v1/pro/graphql/delivery/queries` | List persisted queries |
| `POST /api/v1/pro/graphql/delivery/queries` | Register a persisted query |
| `DELETE /api/v1/pro/graphql/delivery/queries/:id` | Remove a persisted query |
| `POST /api/v1/graphql-delivery/query/:hash` | **Public** — execute a persisted query |
| `GET /api/v1/graphql-delivery/schema` | **Public** — schema for registered clients |
