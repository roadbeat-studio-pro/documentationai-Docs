## Overview

The **Saved Views** plugin lets editors persist their most-used content list configurations — filters, sort order, view mode, and search queries — as named views that can be recalled instantly. Views can be shared with the organization or kept private.

## Key Features

- **Persist filter combinations** — save any content list state (content types, status, languages, authors, date ranges, sort, search, view mode, page size) as a named view; configurations are validated on save
- **Filter builder** — pick content types, statuses, languages, and authors from lists and set date ranges, instead of writing filter JSON by hand
- **Quick recall** — switch between saved views with a single click
- **Default view** — mark a view as your personal default so the content list opens with it
- **Shared views** — share views with the whole organization or only with a specific role
- **Pin favorites** — pin frequently used views to the quick-access bar
- **Drag-and-drop reorder** — reorder pinned views (all-or-nothing; a failed reorder never leaves the bar half-applied)
- **Per-user usage tracking** — accurate usage counts even on shared views
- **Duplicate views** — clone an existing view as a starting point for a new one
- **Icon and color customization** — assign a custom icon and color to each view for quick identification

## For Admins: Setup

### Migrations

The Studio API applies and tracks plugin migrations itself at startup, so these run automatically — a new one takes effect on the next API start. Run them by hand only if you set `PLUGIN_MIGRATIONS=off` because a deploy step applies them; see [Installation](/installation) for details.

```bash
psql -U postgres -d roadbeat_studio -f plugins/pro-saved-views/migrations/001_create_saved_views.sql
psql -U postgres -d roadbeat_studio -f plugins/pro-saved-views/migrations/002_add_user_fk.sql
psql -U postgres -d roadbeat_studio -f plugins/pro-saved-views/migrations/003_add_share_scope.sql
psql -U postgres -d roadbeat_studio -f plugins/pro-saved-views/migrations/004_user_state.sql
```

Tables created: `pro_saved_views`, `pro_saved_view_user_state`

<Callout kind="info">
  Deleting a user also deletes their saved views (including shared ones) — duplicate a shared view worth keeping before offboarding its owner.
</Callout>

### Building the Frontend

The plugin includes an Angular Elements frontend that must be built before the UI is available:

<Steps>
  <Step title="Install dependencies">
    Navigate to the plugin's frontend directory and install packages:
    ```bash
    cd plugins/pro-saved-views/frontend
    npm install
    ```
  </Step>
  <Step title="Build the bundle">
    Build the frontend for development or production:
    ```bash
    # Development (with source maps)
    pnpm run build:dev

    # Production (optimized)
    pnpm run build
    ```
    The compiled bundle is output to `plugins/pro-saved-views/dist/frontend/main.js`.
  </Step>
  <Step title="Verify">
    Confirm the API serves the bundle:
    ```bash
    curl -I http://localhost:3000/api/v1/plugins/pro-saved-views/ui/main.js
    # Expected: HTTP 200, Content-Type: application/javascript
    ```
  </Step>
</Steps>

<Callout kind="info">
  The Studio API serves plugin frontend bundles from `PLUGINS_DIR/{pluginId}/dist/frontend/` via the `PluginAssetsController`. No API restart is needed after building — files are read from disk on each request.
</Callout>

## For Editors: Using Saved Views

### Creating a View

<Steps>
  <Step title="Configure the content list">
    Set up your desired filters, sort order, view mode, and search query in the content list.
  </Step>
  <Step title="Open Saved Views">
    Navigate to **Pro → Saved Views** in the sidebar.
  </Step>
  <Step title="Create a new view">
    Click **+ New View** and fill in:
    - **Name** — a descriptive name (e.g., "Published Events", "Draft Articles")
    - **Description** — optional notes about the view's purpose
    - **View Mode** — table, list, grid, masonry, calendar, map, or globe
    - **Sort By / Sort Order** — choose the field and direction
    - **Page Size** — 25, 50, or 100 items per page
    - **Search term** — an optional saved search query
    - **Filters** — built with the filter builder (see below)
    - **Icon and Color** — visual customization for quick identification
    - **Shared** — toggle to make the view available to others. The share scope is either the **whole organization** (default) or **only users with a specific role** (e.g. share an editorial triage view with editors only).
  </Step>
</Steps>

<Callout kind="alert">
  Sharing exposes the view's **filters and saved search text** to the selected audience — the editor shows a notice when you enable sharing.
</Callout>

### Building Filters

The **Filters** section of the view form builds the same filters the content list uses. Every list is multi-select; leave a group empty to not filter on it.

| Filter | What you pick |
|--------|---------------|
| **Content types** | Any number of your organization's content types — type in the search box to narrow a long list; selected types stay on top |
| **Status** | Draft, Published, Unpublished, Archived |
| **Languages** | The organization's enabled languages (shown when more than one is enabled) |
| **Authors** | Organization members who created the content (shown when you may read the member list) |
| **Published / Created / Updated** | A date range per date; an open end is closed like the content list does — from 1970-01-01, or up to today |
| **Published at least once** | Only content that carries a publish date, i.e. has been published at some point |

<Callout kind="info">
  Filters set in the content list that the builder does not edit — such as type-specific field filters — are **kept** when you save. The form tells you how many there are; click **Remove them** to drop them from the view.
</Callout>

The builder stores the filters under `config.filters` in the content list's own format:

```json
{
  "viewMode": "table",
  "sortBy": "updatedAt",
  "sortOrder": "desc",
  "pageSize": 50,
  "search": "climate",
  "filters": {
    "contentTypeId": ["news", "event"],
    "status": ["draft", "published"],
    "locale": ["de"],
    "createdById": ["<user id>"],
    "publishedDate": { "gte": "2026-01-01", "lte": "2026-06-30" },
    "hasBeenPublished": true
  }
}
```

`createdDate` and `updatedDate` take the same `{ "gte", "lte" }` range as `publishedDate`.

### Default View

Mark any view you can see (own or shared) as your personal default — the content list then opens with it automatically. Each user has at most one default; setting a new one replaces the previous choice atomically.

### Managing Views

From the Saved Views page you can:

- **Apply** — click a view card to load its configuration in the content list
- **Edit** — modify any view's settings
- **Duplicate** — clone a view as a starting point
- **Pin/Unpin** — pin views to the quick-access bar for one-click access
- **Delete** — remove views you no longer need

### View Configuration

Each saved view stores the following settings:

| Setting | Description |
|---------|-------------|
| **View Mode** | Table, List, Grid, Compact Masonry, Large Masonry, Calendar, Map, Globe |
| **Sort By** | Updated, Created, Published, Slug, Title, Status |
| **Sort Order** | Ascending or Descending |
| **Page Size** | 25, 50, or 100 |
| **Search** | Saved search query |
| **Filters** | Content types, status, languages, authors, date ranges, "published at least once", plus any further content list filters — see [Building Filters](#building-filters) |

## API Reference

| Endpoint | Description |
|----------|-------------|
| `GET /api/v1/pro/saved-views` | List all saved views (own + shared) |
| `POST /api/v1/pro/saved-views` | Create a new saved view |
| `GET /api/v1/pro/saved-views/:id` | Get a saved view by ID |
| `PUT /api/v1/pro/saved-views/:id` | Update a saved view |
| `DELETE /api/v1/pro/saved-views/:id` | Delete a saved view |
| `POST /api/v1/pro/saved-views/:id/duplicate` | Duplicate a saved view |
| `PATCH /api/v1/pro/saved-views/:id/pin` | Pin or unpin a saved view |
| `POST /api/v1/pro/saved-views/reorder` | Reorder pinned views (atomic) |
| `GET /api/v1/pro/saved-views/default` | Get your default view |
| `POST /api/v1/pro/saved-views/:id/default` | Set a view as your default |
| `DELETE /api/v1/pro/saved-views/default` | Clear your default view |
