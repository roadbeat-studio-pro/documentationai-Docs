## Overview

The **AI Assistant & Provider Gateway** (`pro-ai`) is the single, governed entry point for every AI capability in Studio. Instead of each plugin wiring its own model keys, the gateway gives you **one place to configure providers, one place to enforce privacy, and one place to meter cost**.

It unifies self-hosted models (Augmentor / Ollama), EU cloud (Mistral, Azure OpenAI EU), and — opt-in — non-EU providers (OpenAI, Anthropic, Google) behind a uniform API. Routing, residency policy, fallback, redaction, consent, budgets, and an append-only audit log are applied to **every** call, no matter which feature triggered it.

<Callout kind="info" collapsed="false">
  `pro-ai` is a **Pro plugin** on the **Team** tier. Core inference, local + EU-cloud providers, translation, writing assistance, embeddings, vision, and the Agent backbone are all Team. Two capabilities require the **Business** tier: non-EU cloud providers and advanced governance. See [Licensing & Feature Gates](#licensing-and-feature-gates).
</Callout>

## Key Features

- **One gateway, many backends** — Augmentor, Ollama, Mistral, Azure OpenAI, OpenAI, Anthropic, Gemini, and any OpenAI-compatible endpoint, all behind a uniform adapter interface
- **Goal-driven routing** — per-task routes pick the right model tier, residency, and provider, with an ordered fallback chain
- **Health-based failover** — a per-provider circuit breaker skips unhealthy backends and records every fallback
- **Privacy by design** — residency modes, PII redaction before cloud egress, explicit non-EU consent, and enforced zero-retention
- **Cost control** — org/per-user token & cost budgets, per-user rate limits, license-tier ceilings, and a burn-down dashboard
- **Structured, schema-first generation** — drafts validated against your content-type JSON Schema (AJV 2020-12) with automatic re-prompting
- **In-editor assistance** — a sidebar assistant and per-field ✨ actions, every suggestion shown as an accept/reject diff
- **Shared backbone** — sibling Pro plugins (e.g. the Studio Agent) consume the same gateway via the `AI_SERVICE` contract; capabilities are also exposed as **MCP tools**
- **Full audit trail** — every call is metered and logged (privacy-preserving hashes by default)
- **SSRF-safe media sources** — image and audio URLs for vision and transcription are fetched under a guard and handed to the provider as data, never as a URL
- **Coded, translated errors** — every failure carries a stable `code` and `params`; a failing provider is a `502` that names it, not an opaque `500`. See [API Error Codes](/help-center/troubleshooting/error-codes)

## Architecture

Every capability flows through the same governed pipeline before a single token leaves your instance:

```mermaid

    A[Editor / Agent / Plugin] --> B[AI Gateway]
    B --> C[Budget & rate gate]
    C --> D[Routing + residency]
    D --> E[Consent & zero-retention]
    E --> F[PII redaction]
    F --> G{Provider}
    G -->|self-hosted| H[Augmentor / Ollama]
    G -->|EU cloud| I[Mistral / Azure EU]
    G -->|non-EU opt-in| J[OpenAI / Anthropic / Gemini]

```

## Capabilities

The gateway exposes a single service surface (`AI_SERVICE`) and a REST API under `/api/v1/pro/ai/*`:

| Capability                        | What it does                                                                                                            | Typical caller              |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| `chat`                            | Streaming chat completion with optional tool-calling                                                                    | Agent, editor assistant     |
| `embed` / `embedBatch`            | Text embeddings (single or chunked batch)                                                                               | Semantic search, dedup      |
| `translate`                       | Plain text, rich-text, or content-wide batch translation (glossary- and tone-aware)                                     | One-click localize          |
| `writeAssist`                     | Editor writing actions (see below)                                                                                      | Field actions, assistant    |
| `generateStructured`              | Schema-grounded drafting validated against a content type's JSON Schema                                                 | Agent, import enrichment    |
| `vision`                          | Image → alt text, caption, OCR, tags, or description — alt-text suggestions are generated in the **organization's default content locale** and carry a locale tag | Alt-text on upload          |
| `transcribe`                      | Audio/video → text                                                                                                      | Media workflows             |
| `classify`                        | Topic/sentiment classification or entity/field extraction                                                               | Moderation, enrichment      |
| `semanticSearch` / `moreLikeThis` | Rank org content by meaning against the pgvector embedding index (`moreLikeThis` is a pure index lookup — no inference) | Discovery, related content  |
| `findNearDuplicates`              | Advisory near-duplicate candidates (vector + lexical shingle overlap; near-verbatim copies flagged)                     | Editor warning, import gate |
| `moderate`                        | Advisory safety/PII pass — pinned to local providers by default so flagged content never leaves the instance            | Publish review              |
| `suggestFacets`                   | Facet values constrained to the content type's enumerated schema vocabulary (hallucination-proof by hard filter)        | Goal-driven tagging         |
| `summarizeForTeaser`              | Teaser fields conforming to the type's teaser schema, honest-framing enforced, AJV-validated                            | Discovery teasers           |

### Writing assistant actions

`writeAssist` supports eleven actions, each returning a structured result for a **diff preview** — text is never auto-applied:

`improve` · `fix` · `shorten` · `expand` · `tone` · `summarize` · `headline` · `dek` · `seo` · `social` · `continue`

List actions (`headline`, `social`) also return parsed `suggestions` so the editor can show selectable options.

### Schema-grounded generation

`generateStructured` injects the target content type's JSON Schema (and any per-type examples), generates a JSON payload, and validates it with AJV (2020-12). On invalid output, the validation errors are fed back to the model for a bounded number of retries, so callers never persist invalid content:

```json
{
  "data": { "title": "…", "summary": "…" },
  "valid": true
}
```

### Image and audio sources

`vision` accepts `imageUrl` or `imageBase64`; `transcribe` accepts `audioUrl` or `audioBase64`. A URL is **never** passed on (SSRF guard): after routing has picked a capable provider, the gateway loads the file itself and hands it to the adapter as a base64 data URI. Neither Studio's adapters nor the provider — including a self-hosted one inside your network — ever fetches a user-supplied URL.

How a source URL is loaded:

| Source | Rule | Error |
|---|---|---|
| URL of **this Studio's own storage** | Read directly from storage, and only if the asset belongs to the caller's organization and is not deleted — no cross-tenant reads by URL | `404 ASSET_NOT_FOUND` |
| Any other URL — scheme | `http` or `https` only, no `user:password@` credentials | `400 AI_REQUEST_INVALID` |
| Any other URL — address | **Every** DNS answer must be a public address. Blocked: `0.0.0.0/8`, `10/8`, `127/8`, `100.64/10` (CGNAT), `169.254/16` (link-local, incl. the cloud metadata endpoint), `172.16/12`, `192.168/16`, `224.0.0.0` and above (multicast/reserved), `::`, `::1`, `fc00::/7` (ULA), `fe80::/10`; IPv4-mapped IPv6 addresses are checked as IPv4 | `400 AI_SOURCE_URL_BLOCKED` `{ hostname }` |
| Any other URL — reachability | Host must resolve and answer within **15 seconds** | `400 AI_SOURCE_UNREACHABLE` `{ hostname }` |
| Redirects | Followed manually, at most **3**, and every hop is checked again | `400 AI_REQUEST_INVALID` (too many) |
| HTTP status | The final response must be `2xx` | `502 AI_SOURCE_FETCH_FAILED` `{ kind, status }` |
| Size | Images at most **20 MB**, audio at most **25 MB** (also for files from own storage) | `400 AI_SOURCE_TOO_LARGE` `{ kind, maxMb }` |

<Callout kind="tip">
  An image on an intranet host is refused with `AI_SOURCE_URL_BLOCKED`. Upload it to the Studio media library (its URL is read from storage directly) or send it as `imageBase64`. The guard applies to **source URLs in requests only** — provider base URLs such as a local Augmentor on `host.docker.internal` are unaffected.
</Callout>

### Adding a provider

<Steps>
  <Step title="Open AI settings" icon="settings" title-type="p">
    Go to **AI** in the Pro section of the sidebar and switch to the **Providers** tab.
  </Step>

  <Step title="Choose a provider type" icon="plug" title-type="p">
    Pick a provider type and give it a name. The API key is stored in the **credential vault** — it is never returned to the frontend, logs, or the model.
  </Step>

  <Step title="Set residency, scope, and priority" icon="shield" title-type="p">
    Set the data residency, whether the key is **org-shared** or a **per-user BYO key**, and a routing priority. Mark a **no-retention** endpoint where the provider guarantees zero data retention.
  </Step>

  <Step title="Test the connection" icon="activity" title-type="p">
    Click **Test** to run a health check. Online providers show latency; offline ones are skipped by routing automatically.
  </Step>
</Steps>

  A caller's **own** provider (a per-user BYO key) takes precedence over the org-shared one for the same provider type and name — so power users can bring their own keys without changing the org default.

### Routing and fallback

The **Routes** tab holds a per-task routing table as JSON: each task maps to a tier, residency, preferred model/provider, and an ordered fallback chain.

```json
{
  "writeAssist": { "tier": "cheap", "residency": "eu_only", "provider": "mistral" },
  "generateStructured": {
    "tier": "heavy",
    "residency": "eu_only",
    "provider": "mistral",
    "model": "mistral-large",
    "fallback": ["augmentor", "azure-openai/gpt-4o"]
  },
  "embed": { "provider": "augmentor", "model": "multilingual-e5-large" }
}
```

Routing resolves the best **healthy** provider that satisfies the residency mode, then walks the fallback chain. A per-provider circuit breaker skips backends that are failing, and every fallback is recorded in the usage log.

### Residency modes

The effective residency mode is resolved per call: a per-call override → the task route → the instance default (`AI_RESIDENCY_MODE`, default `eu_only`).

| Mode         | Allowed providers                                                |
| ------------ | ---------------------------------------------------------------- |
| `local_only` | Self-hosted only (Augmentor / Ollama)                            |
| `eu_only`    | Self-hosted + EU cloud                                           |
| `any`        | All providers, including non-EU (requires consent + entitlement) |

Privacy, consent, redaction, budgets, and the audit trail are documented in detail in [AI Privacy & Governance](/plugins/ai-governance).

## For Editors

When `pro-ai` is active, editors get an **AI Assistant** sidebar and per-field **✨ actions** directly in the content editor — quick actions (including a local **Safety check**, **Suggest tags**, and **Draft teaser**), chat, one-click translation, and alt-text suggestions, each shown as an accept/reject diff so nothing is ever applied silently. Every result carries a **provenance badge** (Local — no egress / EU cloud / Non-EU cloud, with redaction and fallback markers), the sidebar warns about **possible duplicates** of the open item, and the first use of a non-EU provider is blocked behind an inline, logged **consent dialog**. When something fails — in a quick action, a field action, or mid-chat — the panel says what happened in the interface language (for example which provider returned an error, that consent is needed, or that a budget is used up) instead of showing a raw API message.

## Licensing and Feature Gates

`pro-ai` is licensed on the **Team** tier; two capabilities require **Business**. Gates are evaluated through CE's `FeatureGateService`.

| Capability                                                                                                         | Tier         | Gate                         |
| ------------------------------------------------------------------------------------------------------------------ | ------------ | ---------------------------- |
| Inference, local + EU-cloud providers, translation, writing, embeddings, vision, Agent backbone, per-user BYO keys | **Team**     | —                            |
| Non-EU cloud providers (OpenAI / Anthropic / Gemini)                                                               | **Business** | `ai_cloud_providers_enabled` |
| Advanced governance (custom redaction rules, zero-retention overrides, raw-log retention controls)                 | **Business** | `ai_advanced_governance`     |

Without the entitlement, a Business capability answers `403 AI_FEATURE_NOT_LICENSED` with `params: { feature, tier }`.

Two numeric license limits cap org usage **on top of** admin-configured budgets, enforced in the pre-call gate (`429 AI_LICENSE_LIMIT_EXCEEDED` with `params: { kind, period, limit }` on breach):

| Limit                   | Effect                            |
| ----------------------- | --------------------------------- |
| `max_ai_tokens_per_day` | Hard daily org token ceiling      |
| `max_ai_cost_per_month` | Hard monthly org cost ceiling (€) |

<Callout kind="info" collapsed="false">
  Non-EU providers are gated at **routing** time: without `ai_cloud_providers_enabled`, EU/local providers still route normally, and a call is only refused — `403 AI_CLOUD_PROVIDERS_NOT_LICENSED` with `params.providerTypes` — when its _only_ eligible providers are non-EU. See [Licensing](/licensing) for tiers and offline validation.
</Callout>

## Using the Gateway from Other Plugins

Sibling Pro plugins inject the gateway through the shared `AI_SERVICE` token rather than calling models directly — so they inherit routing, residency, redaction, budgets, and audit for free. This is how the **Studio Agent** (Integration Hub) plans multi-tool jobs and drafts schema-valid content, and how CE's auto-translate and alt-text hooks light up when `pro-ai` is installed.

The same capabilities are exposed as **MCP tools** (`GET /api/v1/pro/ai/mcp/tools`, `POST /api/v1/pro/ai/mcp/call`), so external AI tooling can call the governed gateway with the exact same guarantees.

<Callout kind="tip" collapsed="false">
  When `pro-ai` is **not** installed, dependent features degrade gracefully — AI surfaces are hidden and CE auto-translate falls back to its configured machine-translation provider.
</Callout>

## Errors and Failure Handling

Every error from the gateway uses Studio's standard error body with a stable `code` and the values of its message in `params` — the AI screens translate it into the UI language, and API clients can switch on `code` instead of parsing English text. The full contract and every code are listed in [API Error Codes](/help-center/troubleshooting/error-codes#ai-provider-gateway).

| Situation | Status | Code | `params` |
|---|---|---|---|
| The provider answered with an HTTP error | `502` | `AI_PROVIDER_FAILED` | `provider`, `status` |
| The provider host could not be reached or timed out | `502` | `AI_PROVIDER_UNREACHABLE` | `provider` |
| No configured provider satisfies the residency mode | `503` | `AI_NO_PROVIDER` | `mode`, `task` |
| Eligible providers exist, but none is healthy (or none supports the capability) | `503` | `AI_NO_HEALTHY_PROVIDER` | `task` |
| Non-EU provider without consent / without zero-retention under `eu_only` | `403` | `AI_CONSENT_REQUIRED` / `AI_RETENTION_REQUIRED` | `providerTypes`, `providers` |
| Rate limit, budget, license ceiling, velocity guard | `429` | `AI_RATE_LIMITED`, `AI_BUDGET_EXCEEDED`, `AI_LICENSE_LIMIT_EXCEEDED`, `AI_VELOCITY_CEILING`, `AI_VELOCITY_ANOMALY` | the limit that fired |
| Malformed request, or the routed provider lacks the capability | `400` | `AI_REQUEST_INVALID`, `AI_PROVIDER_NO_VISION`, `AI_PROVIDER_NO_TRANSCRIPTION`, `AI_PROVIDER_NO_EMBEDDINGS` | — |
| Provider, prompt or job id unknown **or malformed** | `404` | `AI_PROVIDER_NOT_FOUND`, `AI_PROMPT_NOT_FOUND`, `AI_JOB_NOT_FOUND` | — |
| A provider with that name already exists in the scope | `409` | `AI_PROVIDER_EXISTS` | `name` |

<Callout kind="info">
  The provider's own error response is written to the server log only (first 500 characters) and never returned to the client, because it can echo request content. A provider failure still counts toward that provider's circuit breaker and is metered as a failed call.
</Callout>

### Errors in the chat stream

`POST /chat` answers with Server-Sent Events, so its HTTP status is already `200` when a failure happens — including pre-call refusals such as a missing consent or an exhausted budget. The failure arrives as an `error` event with the same `code` / `message` / `params` as a JSON error, and the stream then closes:

```text
event: error
data: {"code":"AI_CONSENT_REQUIRED","message":"Consent required before using non-EU AI provider(s): openai","params":{"providerTypes":["openai"],"providers":"openai"}}
```

An error without a code is logged on the server and sent as `{"code":"INTERNAL_ERROR","message":"Internal server error"}` — the raw error text never reaches the client. Request-body validation and authentication still fail before the stream starts, with a normal JSON error.
