## Overview

The **Audit Logging** plugin provides a comprehensive, immutable audit trail for all significant actions in Studio. Every content change, user action, and system event is recorded with full context — who did what, when, and exactly what changed.

## Key Features

- **Immutable, tamper-evident entries** — every action is logged with user, resource, changes, severity, and category, linked into a per-organization SHA-256 hash chain
- **Chain verification** — one call walks the chain and reports the first broken link, so silent edits or deletions are detectable
- **Change tracking** — old vs new field values stored as JSONB diffs
- **Compliance reports** — generate GDPR, user-access, data-changes, permission-changes, and API-access reports
- **Complete exports** — download **all** matching audit logs as JSON or CSV (no silent row cap); CSV cells are guarded against spreadsheet formula injection
- **GDPR erasure support** — when a user is erased, their audit rows are pseudonymized in place and the chain is re-linked
- **Retention policies** — configurable auto-cleanup rules (30–3,650 days)
- **Saved searches** — save and share filter combinations for repeated queries
- **Analytics dashboard** — breakdowns by action, resource, severity, category, and top users
- **Event-driven** — automatically captures content and user lifecycle events

### Migration

```bash
psql -U postgres -d roadbeat_studio -f plugins/pro-audit/migrations/001_create_audit_tables.sql
psql -U postgres -d roadbeat_studio -f plugins/pro-audit/migrations/002_add_saved_searches.sql
psql -U postgres -d roadbeat_studio -f plugins/pro-audit/migrations/003_add_source.sql
psql -U postgres -d roadbeat_studio -f plugins/pro-audit/migrations/004_tamper_evidence.sql
psql -U postgres -d roadbeat_studio -f plugins/pro-audit/migrations/005_gdpr_scrub.sql
```

Tables created: `pro_audit_logs`, `pro_audit_retention_policies`, `pro_audit_saved_searches`

### Tamper Evidence

Every entry carries `prev_hash`/`entry_hash` links in a per-organization hash chain, and an append-only database trigger blocks UPDATE/DELETE outside the two sanctioned paths (retention and GDPR scrub). Verify the chain any time:

```bash
GET /api/v1/pro/audit/verify
# → { valid: true } or the first broken link with its position
```

Retention deletions write a **checkpoint entry** anchoring the hash of the last removed row, so pruning old logs never breaks verifiability. The verification run itself is recorded as an audit entry.

### GDPR Erasure

When CE erases a user (GDPR Art. 17), the plugin **pseudonymizes** that user's audit rows in place — identity fields are replaced with a stable HMAC pseudonym so per-actor analytics still work — and the hash chain is re-linked with a scrub checkpoint recording what happened.

### Automatic Event Capture

The plugin automatically logs these events:

| Event | Severity | Category |
|-------|----------|----------|
| Content created | `info` | `content` |
| Content updated | `info` | `content` |
| Content deleted | `warning` | `content` |
| Content published | `info` | `content` |
| User created | `info` | `user` |
| User updated | `info` | `user` |
| User deleted | `warning` | `user` |

### Retention Policies

Configure how long audit logs are retained:

<Steps>
  <Step title="Navigate to Audit Log">
    Go to **Audit Log** in the Settings section of the sidebar.
  </Step>
  <Step title="Open the Retention tab">
    Switch to the Retention tab to manage retention policies.
  </Step>
  <Step title="Create a policy">
    Define a retention period (30–3,650 days), category filter, and severity filter. Logs matching the policy are automatically deleted after the retention period.
  </Step>
  <Step title="Enforce manually (optional)">
    Click **Enforce Now** to immediately apply retention policies and delete expired logs.
  </Step>
</Steps>

### Compliance Reports

Generate compliance reports from the **Compliance** tab:

| Report Type | Description |
|------------|-------------|
| `user-access` | All actions by a specific user in a date range |
| `data-changes` | All content modifications with before/after values |
| `permission-changes` | Role and permission modifications |
| `api-access` | API key usage and access patterns |
| `gdpr-data-export` | Full GDPR data export for a specific user |

Reports can be exported as JSON or CSV.

<Callout kind="info">
  **Exports are complete and spreadsheet-safe.** The export endpoint pages through
  *all* matching rows (the response carries the real total in `X-Total-Count`),
  and CSV cells that start with `=`, `+`, `-`, or `@` are neutralized so stored
  values can never execute as formulas on an auditor's machine.
</Callout>

## For Editors: Viewing Audit Logs

Editors with appropriate permissions can browse the audit log to see:

- **Activity timeline** — chronological list of all actions
- **Filters** — by user, action, resource type, severity, category, date range, and free-text search
- **Detail view** — expand any entry to see the full change details (old vs new values)
- **Saved searches** — save frequently used filter combinations for quick access

<Callout kind="tip">
  Use the saved search feature to create common views like "My changes this week" or "All published content today".
</Callout>

## API Reference

All audit endpoints are in the [Studio API Reference](https://docs.studio.roadbeat.dev/api-reference/overview) under the audit-related tags.

| Endpoint | Description |
|----------|-------------|
| `GET /api/v1/pro/audit` | Query audit logs with filters |
| `GET /api/v1/pro/audit/entry/:id` | Get single audit entry |
| `GET /api/v1/pro/audit/export` | Export logs (JSON/CSV) |
| `GET /api/v1/pro/audit/stats` | Analytics dashboard data |
| `GET /api/v1/pro/audit/verify` | Walk the tamper-evidence hash chain |
| `GET /api/v1/pro/audit/retention` | List retention policies |
| `POST /api/v1/pro/audit/retention/enforce` | Enforce retention now |
| `GET /api/v1/pro/audit/searches` | List saved searches |
| `POST /api/v1/pro/audit/compliance/generate` | Generate compliance report |
