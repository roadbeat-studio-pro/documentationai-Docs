<Update label="2026-08-01" description="Data, integrations & APIs — security hardening, delivery reliability, and feature completion across 8 plugins" tags={["feature","security","bugfix"]}>
  ## Data, Integrations & APIs Overhaul

  An audit-driven pass over the eight data/integration plugins (`pro-import`,
  `pro-export`, `pro-bulk-ops`, `pro-media`, `pro-graphql`,
  `pro-api-explorer`, `pro-webhooks`, `pro-integrations`): credential and
  tenancy fixes, GDPR retention, delivery reliability, and a wave of feature
  completion.

  ### Security & multi-tenancy

  - **Cross-tenant credential use closed** — engine credential leases are
    organization-scoped, so a connection id lifted from an edited flow
    definition can no longer lease another tenant's secret. Leases now also
    expire instead of being advisory.
  - **Vault keys fail closed** — `INTEGRATIONS_KEK` and `PRO_AI_VAULT_KEK` are
    **required in production**; the vault refuses to start rather than falling
    back to a source-derivable dev key. A malformed key always throws.
  - **CSV formula injection fixed** — exported cells starting with `=`, `+`,
    `-`, `@`, tab, or carriage return are neutralized so they display as text
    instead of executing when the file is opened in Excel or LibreOffice.
    `EXPORT_CSV_RAW=true` opts out for machine-to-machine pipelines.
  - **Bearer tokens no longer persisted** in API Explorer history —
    credential-bearing headers are redacted before the row is written, replay
    uses the *current* caller's credentials, and cURL export emits a
    placeholder with correct POSIX quoting instead of the live token.
  - **Webhook signatures verify the raw request bytes** rather than a
    re-serialized body, with a timestamp window and single-use nonces; the
    public inbound endpoint is rate-limited and its nonce table self-prunes.
  - **Incoming-webhook secrets are show-once** — returned at creation and
    regeneration only; list and detail responses carry a masked hint.
  - **SSRF guards extended** — MCP server registration validates the URL it
    fetches, asset-import downloads reject private and internal addresses, and
    the guard now catches hosts written with an explicit port.
  - **Org scoping fixes** — incoming `update_content` actions, webhook
    retry-config fallback, and media worker job mutations are all
    organization-scoped.

  ### Privacy & GDPR

  - **Retention windows everywhere** — export files (7 days), webhook delivery
    and incoming logs (30), API-Explorer history (30), and the bulk-ops asset
    trash (14) are pruned automatically. Each is configurable per organization
    within a clamped range.
  - **Deletion means deletion** — expired exports remove the storage object as
    well as the database row; purging the asset trash removes every storage
    object; a rolled-back import deletes the assets it downloaded.
  - **Data minimization** — sensitive request headers are redacted before
    logging, and saved API-Explorer rows keep the request but drop the stored
    response body.

  ### Reliability & correctness

  - **Webhook retries are delivered by a background processor** with atomic
    claiming, so retries no longer require a manual API call and two nodes do
    not double-send. DLQ retries re-enter the queue instead of parking in a
    state nothing processed.
  - **DLQ email alerts** finally send, debounced per webhook so one outage is
    one email.
  - **Schedule and poll triggers claim each firing atomically** — a two-node
    deployment fires them once, not twice. OAuth token refresh is guarded
    against the refresh-rotation race.
  - **Media jobs recover** — a job whose worker died is requeued instead of
    sitting in `processing` forever, jobs can be cancelled, and an attempt
    ceiling stops infinite retries.
  - **GraphQL correctness** — the generated SDL is valid for any number of
    content types, every advertised filter operator actually executes
    (`in`, `notIn`, `endsWith`, nested `AND`/`OR`), and numeric/date fields
    compare as numbers and dates rather than as text. Depth, complexity, and
    rate limits are enforced instead of merely stored.
  - **Exports keep all columns** — the CSV header is the union of every
    record, not just the first, so fields present only in later records are no
    longer silently dropped. Large exports stream to object storage instead of
    buffering into a database column.
  - **Import fixes** — retrying an import re-runs only the failed rows, a
    failed rollback keeps its tracking rows so it can be retried, and stale
    jobs are swept rather than wedging forever.
  - **Bulk results are honest** — responses distinguish changed, unchanged,
    not-found, and deliberately skipped ids instead of silently dropping them.

  ### New features

  - **Three new import formats** — XML with a record selector, WordPress WXR
    with a post-type picker and preset field mapping, and Markdown with
    frontmatter (single file or ZIP bundle). Plus `asset` and `relation`
    transforms that turn an image URL into a Studio asset or resolve a foreign
    value into a content relation.
  - **Scheduled exports** — run a template on a cron schedule and deliver the
    file to an S3-compatible bucket (SigV4-signed, so European and
    self-hosted endpoints work) or an HMAC-signed webhook, with full run
    history. Delivery credentials are encrypted per organization.
  - **Self-hosted video worker** — ffmpeg-based transcoding, thumbnails, and
    metadata run on your own infrastructure; quality ladders produce several
    renditions per job into a per-asset rendition registry.
  - **Captions** — WebVTT upload per locale across the 24 EU locales, with
    optional transcription via a **local** engine (`MEDIA_TRANSCRIBE_URL`);
    there is no cloud fallback.
  - **Bulk operations grew up** — an undo window with an asset trash, an
    operation log, presigned download URLs, a server-side ZIP, and bulk
    publish/unpublish/archive/delete for **content**, delegated to Studio's own
    content service so versions and events behave exactly as they do for a
    single item.
  - **GraphQL Content Delivery API** — a token-authenticated public endpoint
    serving registered persisted queries, with per-token CORS and scoped draft
    visibility.
  - **API Explorer environments** — per-organization variables with
    `{{variable}}` substitution, secrets encrypted and never returned, plus
    Postman v2.1 collection export in which tokens become collection variables
    so no credential material leaves Studio.
  - **The endpoint catalog is generated from the OpenAPI document**, so it can
    no longer drift from the real API.

  ### Notes for operators

  - Set `INTEGRATIONS_KEK` (and `PRO_AI_VAULT_KEK`) before deploying — the
    vaults now refuse to start in production without them.
  - New migrations ship for `pro-import`, `pro-export`, `pro-bulk-ops`,
    `pro-media`, `pro-graphql`, `pro-api-explorer`, and `pro-webhooks`; see
    each plugin page for the exact list.
  - `ffmpeg` and `ffprobe` must be installed wherever the media worker runs.
    Set `MEDIA_WORKER_ENABLED=false` on nodes that should not process video.
  - Existing Slack/Teams/Discord channels configured before this release are
    unaffected; the media, export, and webhook retention defaults apply
    immediately and can be overridden per organization.
</Update>

<Update label="2026-07-31" description="Editorial & collaboration suite — tenancy hardening, reliability, and feature completion across 8 plugins" tags={["feature","security","bugfix"]}>
  ## Editorial & Collaboration Suite Overhaul

  A full audit-driven pass over the eight editorial/collaboration plugins
  (`pro-workflows`, `pro-scheduling`, `pro-locking`, `pro-versioning`,
  `pro-realtime`, `pro-notifications`, `pro-saved-views`, `pro-preview`):
  multi-tenancy and transport-security fixes, correctness under concurrency,
  crash recovery, and a wave of feature completion.

  ### Security & multi-tenancy

  - **Zero-leakage enforcement everywhere** — workflow instances/tasks,
    scheduled actions, releases, and locks are strictly organization-scoped;
    content ownership is verified before any schedule, lock, or workflow is
    attached. Cross-tenant reads, cancels, and lock-DoS are no longer possible.
  - **WebSocket handshakes are now cryptographically verified** against
    Studio's JWT secrets (rotation-aware) and restricted to your
    `CORS_ORIGINS`; presence is org-isolated.
  - **SQL injection fixed** in the notifications plugin (list filter,
    preference and channel updates, housekeeping) — all raw SQL is
    parameterized.
  - **Channel webhook egress hardened** — HTTPS-only, official-domain
    allow-lists for Slack/Teams/Discord, private/metadata addresses rejected;
    non-EU channels require an explicit **EU data-transfer acknowledgement**
    (existing Slack/Teams/Discord channels are disabled until re-acknowledged).
  - **Preview privacy** — raw visitor IPs are no longer stored (existing data
    wiped); analytics are opt-in per link via salted hashes with a retention
    window. Public preview routes are rate-limited with password lockout;
    tokens move to headers; timing-safe password verification.
  - **Data minimization** — lock payloads no longer expose user emails;
    version author lookups return names only.

  ### Reliability & correctness

  - **Workflow transitions are concurrency-safe** (racing transitions →
    `409 Conflict`, history appended in SQL) and enforce `requiredRoles` /
    `requiresComment` server-side; the publish guard now works with
    custom-named states via `isFinal` / `allowsPublish`.
  - **Scheduling survives crashes** — stale claims from dead replicas are
    reaped and retried with backoff (`SCHEDULING_MAX_ATTEMPTS`); terminal
    failures notify the creator; failed releases can be retried
    (only failed items re-run). Release scheduling/publishing is
    **preflight-validated** (existence, org, workflow approval, conflicts).
  - **Lock acquisition is race-proof** (conditional takeover in SQL) and locks
    release **within seconds of a tab close** via `sendBeacon`; the lock guard
    now also blocks delete and publish of foreign-locked content.
  - **Preview max-views is enforced atomically** — concurrent access can no
    longer exceed the limit.
  - Route-ordering fixes: `DELETE /pro/notifications/read` and
    `DELETE /pro/preview/tokens/cleanup` no longer shadowed by `:id` routes.

  ### New features

  - **Workflow definition versioning** — structural edits create a new
    version; in-flight content stays pinned to its version, with an explicit
    instance-migration endpoint. Per-state **task rules** auto-create review
    tasks (least-loaded role assignment, SLA due dates), and overdue tasks
    remind assignees / escalate to admins.
  - **Recurring schedules** — daily/weekly/monthly publish/unpublish rules
    (RFC 5545 subset) firing at DST-correct local wall-clock times.
  - **Version retention & GDPR redaction** — per-org keep-last/max-age
    pruning, and field-level erasure across *all* historical versions with an
    audit trail. Diffs are now **path-addressed** (`title.de`, not JSON blobs)
    with ordered LCS word-level highlights; version lists are paginated with
    author names; the restore dialog previews exactly what would change.
  - **Notifications went multilingual** — message keys render in each
    recipient's locale (24 EU languages); preferences (per-type, mute, DND)
    are actually enforced; hourly/daily/weekly **digests** batch delivery and
    DND defers instead of dropping; automatic retention purge; external
    channels now really fire on events.
  - **Lock takeover flow** — blocked editors request access, holders are
    notified, force-unlocks are audited (`GET /pro/locking/audit`); lock TTL
    is configurable (`LOCK_TTL_SECONDS`) and lock messages are localized.
  - **Multi-instance realtime** — Socket.IO Redis adapter fans broadcasts
    across replicas; typing indicators; precise presence cleanup (no more
    ghost editors); cursor flood protection.
  - **Saved views** — role-scoped sharing, config validation, atomic pin
    reordering, per-user **default view**, and accurate per-user usage stats.
  - **Reviewer-ready previews** — per-link field redaction (server-side),
    configurable watermark, and external **reviewer comments** tied to the
    link.

  ### Upgrade notes

  - Apply the new migrations for all eight plugins (see each plugin page).
  - Existing Slack/Teams/Discord notification channels are **disabled** until
    re-enabled with `dataTransferAck: true`.
  - Previously collected raw visitor IPs on preview links are **deleted** by
    the preview migration.
</Update>

<Update label="2026-07-30" description="pro-ai v1.0.0 — content intelligence, sovereignty transparency & cost resilience" tags={["feature","security"]}>
  ## AI Assistant & Provider Gateway v1.0.0

  The `pro-ai` plugin reaches **v1.0.0** with a wave of content-intelligence and
  governance features:

  ### Content intelligence

  - **Semantic search & "more like this"** — a pgvector-backed embedding index
    (kept in sync on every content save, with hash-skip so unchanged saves cost
    nothing) powers `GET /pro/ai/search` and per-item similarity lookups.
    Local-first: indexing uses the pinned EU/self-hosted embedding model.
  - **Near-duplicate warnings** — the editor sidebar flags possible duplicates
    of the open item (vector similarity + lexical overlap; near-verbatim copies
    called out), and `POST /pro/ai/dedup` gates imports. Advisory only — nothing
    is ever removed automatically.
  - **Advisory safety check** — an editor-triggered moderation pass
    (hate/harassment/sexual/violence/illegal + PII-in-public-content via your
    redaction rules), **pinned to local providers by default** so flagged
    content never leaves the instance. Escalation to soft/hard block is org
    policy.
  - **Schema-aware tagging & teaser drafting** — facet suggestions constrained
    to the content type's enumerated vocabulary (hallucination-proof by hard
    filter) and teaser drafts validated against the type's teaser schema under
    the honest-framing policy.

  ### Sovereignty made visible

  - Every AI result carries a **provenance badge** — where it ran (Local — no
    egress / EU / Non-EU), which model, whether PII was redacted, whether a
    fallback served it.
  - First use of a non-EU provider is blocked behind an inline, **logged consent
    dialog**; the providers tab opens with an **egress-posture card** stating
    whether content can ever leave the EU.

  ### Hardening & operations

  - **Prompt-injection defense** standardized across every surface that ingests
    external text or images, backed by an adversarial test corpus in CI.
  - **Spend-velocity safety net** — automation callers (agent, flows, jobs) get
    a hard short-window token ceiling independent of monthly budgets; org-wide
    spend anomalies raise admin alerts. Circuit-breaker opens are emitted as
    events.
  - **Prometheus metrics** — the seven `ai_*` metrics now export through
    Studio's `/metrics` endpoint. See [Provider Setup Recipes](/plugins/ai-recipes#monitoring).
  - **All 24 EU languages** — the AI admin and editor surfaces ship complete
    catalogs, with key parity enforced in CI.
  - **Per-field apply** — accepted ✨ suggestions now edit the form field in
    place in the Studio editor (previously clipboard-only).

  <Callout kind="info" collapsed="false">
    New here? Start with the [Provider Setup Recipes](/plugins/ai-recipes) —
    local Augmentor, Mistral (EU), Azure OpenAI (EU), and per-user BYO keys.
  </Callout>
</Update>

<Update label="2026-07-03" description="Plugin security hardening, reliable workflow automation & content templates" tags={["security","feature"]}>
  ## Security hardening across Pro plugins, plus reliable workflow automation

  ### Security

  A hardening sweep closed several issues found while bringing every Pro plugin
  under test:

  - **SSO — SAML is now fail-closed.** SAML assertions are signature-verified
    against your IdP certificate; a config without a valid certificate, or an
    assertion whose signature fails, is rejected. OAuth/OIDC client secrets are
    now **encrypted at rest** (AES-256-GCM, keyed by `PRO_SSO_SECRET_KEY`). See
    [SSO](/plugins/sso#setting-up-saml-2-0).
  - **API Explorer — SSRF closed.** Request targets are constrained to the
    configured API origin, so a crafted endpoint can no longer be used to reach
    internal hosts. See [API Explorer](/plugins/api-explorer).
  - **Preview — tighter token scope.** Draft preview tokens are validated and
    scoped so a token can only reveal the content it was issued for.
  - **Layouts — parameterized queries** for custom-layout metadata (removes a SQL
    injection vector).

  ### Workflow automation now actually fires

  Several plugins declared event handlers that were never invoked — these are now
  correctly wired, so the automation they promised runs:

  - **Workflows** — the publish guard now enforces required approvals (previously a
    dead handler let content through), and workflow task/transition events fire.
  - **Notifications** — workflow task assignments, transitions, comments, and
    @mentions now generate in-app notifications.
  - **Audit** — content and user actions are logged as intended.
  - **Locking** — the content-lock guard is enforced.

  ### New

  - **Content templates (Workflows)** — start new content from reusable templates.
  - **Scheduling** — the scheduler is now timezone-correct and safe to run across
    multiple instances (no double-execution). See [Scheduling](/plugins/scheduling).
</Update>

  ## Integration Hub — Connectors, Flows & Studio Agent

  The **`pro-integrations`** plugin documentation is now published: a goal-driven automation platform behind a European, privacy-first governance plane.

  - **Connectors** — a governed catalog of external tools: flow-engine native nodes, community pieces, MCP servers, an OpenAPI 3.x importer, and generic primitives (HTTP, webhook in/out, SQL, FTP, S3, email, SSH), each with a maturity badge and data-residency label
  - **Connections + credential vault** — OAuth2 (PKCE), API-key, and Basic auth, encrypted at rest with AES-256-GCM and a per-org data key; secrets are never returned to the frontend, stored in the engine, or sent to the model, and are leased just-in-time per call
  - **Flows** — a portable, engine-agnostic `FlowDefinition` (Input → Check → Decide → Act → Report) with immutable versioning, a phase-laned visual builder, an Edit-JSON escape hatch, and all six trigger types (content event, schedule, HMAC-verified inbound webhook, manual, connector event, agent)
  - **Run orchestration** — governed step execution with sha256 hashes (never raw PII), egress enforcement, HITL pauses, and retry/dead-letter replay using the spec-67 backoff
  - **Studio Agent** — a natural-language planner over a governed tool registry (Studio ops, flows, connector actions, MCP tools, AI utilities), with Assist/Auto modes, schema-validated content writes, prompt-injection guards, and per-call confirmation for anything destructive or egress-bound — requires `pro-ai`
  - **AI flow authoring** — describe a flow in natural language and review the generated graph before activation (Business, requires `pro-ai`)
  - **Governance plane** — per-org egress policy (allowlist / blocklist / eu\_only), always-on SSRF guard, consent ledger, field-level redaction, append-only GDPR-exportable audit, publish guards, rate/quota limits, anomaly detection, and zero-leakage multi-tenancy
  - **Engine** — Activepieces (MIT) sidecar on a private network, swappable via a `FlowEngineAdapter`; isolated so a runaway flow can never crash CE
  - **Licensing** — Team (Connectors + Flows); Business (Agent, AI authoring, advanced governance); Enterprise (federation). Numeric limits `max_flows`, `max_connections`, `max_flow_runs_per_day`, `max_agent_tokens_per_day`
  - **Localized admin UI** — every surface translated across the core EU locales (de, fr, es, it, nl, pl, pt), with English fallback for the rest

  New pages: [Integration Hub](/plugins/integrations), [Integration Hub Governance](/plugins/integrations-governance), [Connector Authoring](/plugins/integrations-connectors), and [Flow Recipes](/plugins/integrations-recipes).
